## 1. Final research question

**Can a dishonest client obtain LLM inference value while under-paying an honest
provider, and how does that depend on where a metering architecture places
synchronization, economic commitment, and usage authority?**

Sub-questions: how much value can be evaded (RQ2), which failures are visible to the
application's own logs (RQ3), and which server-side primitives close each violation and
at what cost (RQ4).

## 2. Final threat model

Honest provider; dishonest client with valid credentials. It controls exactly six
things, each exercised by the harness: request payloads including client-declared usage
fields; permitted headers; concurrency; the connection lifecycle (may abort at any
moment); retries; and observation of its own responses and balance. It **cannot**
compromise TLS, reach the database or Redis, read the gateway filesystem, compromise the
inference backend, forge authenticated upstream metadata, or alter server code. A
concrete application-layer adversary, not a symbolic cryptographic one. Consequently
every measured leak is attributable to the provider's own accounting design, not to a
compromise.

|---|---|---|---|

## 4. Final invariant

For request `r`, with delivered value `V(r)`, committed debits `D(r)`, refunds `F(r)`,
and net committed debit `N(r) = D(r) − F(r)`:

```
Leak(r)      = V(r) − N(r)
Integrity(r) : V(r) ≤ N(r)
```

The inequality is on the **net** debit so that legitimate reconciliation is admitted; a
refund is legitimate only when it releases the unconsumed portion,
`F(r) ≤ Res(r) − V(r)`. The vulnerable "refund the whole reservation on abort"
architecture violates exactly this side condition. System-level conservation
`Σ N(r) = B_init − B_final` is asserted independently on every trial.

M1 is further decomposed into two **orthogonal** properties:
*Property A (solvency)* served value must not exceed the affordable balance;
*Property B (accounting finality)* delivered value must not exceed the net committed
debit.

## 6. Main results

**B0 (baseline).** Leak is $0.000 at concurrency 1, then $0.099 / $2.871 / $4.851 at
c = 2 / 30 / 50 — exactly linear (slope **0.099 per additional concurrent request,
R² = 1.0000, p = 1.9×10⁻⁵⁰**). Hardened atomic compare-and-decrement: **$0 at every
level**.

**M1.** Leak per request tracks value delivered before the missing commit:
0.0045 (≈1 token) → 0.0285 (25%) → 0.0540 (50%) → 0.0960 (90%) → **0.0000 at 100%**
(the debit finally fires). Request-ASR = 1.00 at every abort point before completion;
safe architectures 0.00 everywhere. Honest-client control leaks 0.0000 everywhere.

**M2.** Client-authoritative billing leaks; every server-authoritative architecture
(`server_recount`, `hybrid_reconcile`, `upstream`) leaks **0.000** for all 8
manipulations. Success is determined by whether the pricing basis reads the field the
transformation changes:

| manipulation | vector change | category basis | flat-total basis |
|---|---|---|---|
| under-report output 90% | output 60→6 | **+0.583** | **+0.525** |
| drop reasoning | reasoning 30→0 | **+0.324** | **+0.266** |
| reclassify to cached | output→cached | **+0.313** | −0.058 (total unchanged) |
| total/subtotal mismatch | total 98→24 | 0.000 (basis ignores total) | **+0.741** |

**Recount cost, three levels.** Standalone: linear in length (log–log slope 0.999–1.14,
R² ≥ 0.998), 16,384-token p50 spans **10.1–41.8 ms** across engines (2.9–3.6×
implementation effect). Gateway with a *mock* generator: 0.96–1.00× at ≤1,024 tokens,
**0.05–0.76×** at 16,384 (Spearman ρ = −0.868, p = 1.3×10⁻⁵). Local real model:
**well under 0.1% of end-to-end** (0.014–0.019% at 64 new tokens; an independent
re-measurement with separately written timing code gave 0.017–0.028% at 32 new tokens —
same order of magnitude, the ratio rising as generation shortens).

## 7. Strongest empirical result

**Usage computation is not usage authority.** The `client_logged` architecture performs
a correct, authoritative server-side recount, logs it — and still leaks at efficiency
**0.583**, because billing continues to use the client's number. Combined with the
formal `P(T(U))` analysis showing the exploitable manipulation set is a property of the
*billing basis* rather than attacker ingenuity, this converts "validate your inputs"
into a precise, measured architectural requirement: the recount must be **authoritative
for billing**, not merely computed. A correct-but-unused recount buys detection (D1),
never prevention.

## 8. Strongest negative result

**Concurrency is not an amplifier of client-side metering evasion.** With request volume
held constant, M1 leak per request is **0.0528 at c = 1, 5, 20, 50 and 100 — identical to
four decimal places** — and M2 leakage efficiency is likewise invariant; request-ASR is
exactly 1.000 or 0.000 at every level. Only B0, the synchronization baseline, is
concurrency-created. This is predicted by the state model (transition *atomicity* is a
shared-resource property; the transition *graph* and *data authority* are per-request
properties) and it matters operationally: an operator cannot infer safety from low
traffic, nor detect M1/M2 by watching for load spikes.

## 9. Defense results

Under every defense the invariant-violation rate and leakage efficiency are **zero**
across the full attack catalogue. The ablation shows *which* primitive is load-bearing:

| architecture | Property A: solvency | Property B: accounting integrity | how it fails |
|---|---|---|---|
| `pre_debit` | HOLDS | HOLDS | — |
| `reserve_reconcile` | HOLDS | HOLDS | — |
| `reserve_refund_on_abort` | VIOLATED | VIOLATED | served 6/6 on a 2-request budget |
| `no_reserve_settle` | VIOLATED | **HOLDS** | served 6/6; balance −0.320 |
| `post_completion` | VIOLATED | VIOLATED | served 6/6 on a 2-request budget |

**Reservation and abort-safe finalization are orthogonal controls; neither substitutes
for the other.** `no_reserve_settle` is the decisive cell: finalization alone preserves
accounting integrity but drives the balance negative.

**Lifecycle robustness.** Across 9 injected failure modes (disconnect at t=0 and
mid-stream, truncated stream, settle-window race, missing/delayed/duplicated usage
metadata, recount-engine failure), every invariant violation falls on a vulnerable
architecture, hardened architectures survive all of them, and recount-engine failure is
**fail-closed** (request rejected, nothing served or billed).

**Detectability — WITHDRAWN.** This report previously stated that `client` = D0
(invisible), `client_logged` = D1 (reconcilable) and the server-authoritative
architectures = D3. That claim is **retracted**. The independent audit showed the levels
were *emitted* by the code under test (`"D3" if arch.safe else "D0"`), never measured. An
evidence-only reclassification finds `client` and `client_logged` retain **identical**
evidence and are therefore equally reconcilable, **2,200** stored-D0 records are D1 or D3
on the evidence, and **no record in the study qualifies as D0 at all**. The paper makes no
detectability claim; see `audit/confirmation_bias.md` and `experiments/detectability.py`.

## 11. Statistical assessment

Methodology documented in `paper/statistical_analysis.md`; output in
`results/tables/stats_output.txt`.

- **Deterministic conditions are handled honestly.** Many quantities have structurally
  zero variance (identical input, identical code path). For those the script reports the
  constant and *complete separation* and explicitly declines to compute a p-value.
- **Randomness is analyzed nonparametrically** where it genuinely exists: Mann-Whitney,
  Kruskal-Wallis, Spearman, and percentile bootstrap CIs (10,000 resamples) for skewed
  small-n timing data; Wilson intervals for proportions at extreme p.
- **Effect sizes** (Cohen's d *and* Cliff's delta) accompany comparisons; Cliff's delta
  is reported because d is undefined/infinite under zero variance.
- **No p-value is thresholded to support any conclusion**; no ANOVA is forced onto a
  design where architecture is a perfect predictor; no post-hoc exclusions were made.
- **Sample sizes are derived from measured dispersion**, not convention (adaptive
  tokenizer budget; median-of-3 for noisy gateway cells; 30 reps/cell for B0).
- **Impossible values were treated as evidence of noise, not signal**: real-model
  throughput ratios >1.0 with sign flips across workloads are reported as a ±10% noise
  band ~700× larger than the effect being measured.

## 12. Limitations

1. **Small local CPU model** — bounds a ratio in one configuration; says nothing about
   commercial serving stacks.
2. **Single uvicorn worker, single node, loopback** — gateway recount numbers are an
   upper bound; no multi-tenant contention, no distributed gateway, no multi-region.
3. **M1/M2 are type-B reframings**, not novel primitives.
4. **Gateway measurements at c ≥ 50 are unreliable** (repeat spread to 17%,
   non-monotonic baseline, client/event-loop saturation) and are confined to the
   limitations section; only c = 1 and c = 10 are treated as evidence.
5. **Architecture coverage is representative, not exhaustive** (e.g. deferred batch
   reconciliation, which would land at D1, is not implemented).
6. **Synthetic pricing** and a token-count abstraction of "inference value"; efficiency
   rather than dollars is the headline for this reason.
7. **Literature gap is a bounded negative** from a targeted search in a fast-moving
   area; it does not establish non-existence.
8. **Disconnect-timing jitter** at c ≥ 50 changes delivered tokens by whole-token
   increments (documented in `paper/reproduction_consistency.md`); the accounting
   identity holds exactly in every case.

## 17. Corrections resulting from independent audit

An adversarial integrity audit (`AUDIT_REPORT.md`) was run against this project with the
explicit goal of breaking it. It succeeded in six places. All six are now closed, and the
corrections are listed here rather than absorbed silently, because the direction of every
correction is the same: **the project now claims less than it did.**

1. **Detectability (D0–D3) — withdrawn entirely.** The levels were emitted by the code
   under evaluation and read back as a result. An evidence-only classifier contradicts
   the published distinction: identical evidence for `client` and `client_logged`, 2,200
   label disagreements, and an empty D0 category. No weaker version is reported.
2. **Concurrency — split into empirical and analytic.** B0's slope and M1's invariance
   are empirical; M2's invariance is a derivation the experiment can only confirm. The
   claim matrix gained an `ANALYTICALLY DERIVED` class to make the distinction
   expressible at all.
3. **Backend generality — 17/17 restated as 8.** Only eight of seventeen cells genuinely
   exercised both storage backends; five agree analytically and four are B0 cells that
   ran identical code twice. B0's storage independence is now declared untested.
4. **M2 independence — re-established.** The previous "independent" checker inherited the
   gateway's own ground truth. It was replaced by a specification-derived model that
   shares no code with the project: 0 mismatches.
5. **Attacker knowledge — disclosed.** The harness grants oracle knowledge of true usage.
   A K0/K1/K2 grading is now in the threat model; the headline attack is K0-feasible, and
   the two manipulations that are not are labelled and excluded from the main claim.
6. **Real-model timing — independently re-measured.** Previously reported from a single
   pipeline and never re-checked. Re-timing with separate code confirms the order of
   magnitude and the wording was widened accordingly.

**What survived unchanged:** the accounting core. Independent recomputation from raw data
with zero project imports reproduces 4,800 M2 records, 2,400 M1 records and 420 B0 trials
with **0 discrepancies**, and the B0 slope at 0.099 (R²=1.0000). No raw data was deleted
or adjusted; the retracted `detection_level` field remains in stored records so historical
runs stay byte-reproducible. The failures were concentrated entirely in the interpretive
layer — the places where the artifact described an outcome instead of measuring one —
which is the finding recorded in `audit/confirmation_bias.md`.
